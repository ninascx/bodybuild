## Anti-Patterns Verdict

### LLM assessment

页面存在中等偏高的 AI 模板感。问题不是渐变或阴影，而是典型的“把所有有用信息都做成卡片并同时展示”：三栏仪表盘、等权边框、重复完成度、重复历史入口和嵌套面板。它更像需要解读的管理后台，而不是可以迅速写完离开的训练笔记。

### Deterministic scan

检测命令扫描了 DailyRecordTab、daily 组件、QuickRecordSection 和 NumberField，返回空数组，0 条规则命中、0 个受影响文件。这个结果说明没有明显的静态样式反模式，但无法证明信息架构或可访问性良好。

人工源代码检查额外发现：AppShell 已使用 main，DailyRecordTab 内又嵌套 main；快捷微调的 aria-label 放在无语义 div 上；身体数据的 Suspense 使用空 fallback。

### Visual overlays

应用内浏览器返回 `Browser is not available: iab`，浏览器列表为空，因此无法创建新标签页、执行可变注入或显示检测覆盖层。没有可靠的用户可见覆盖层。本次使用 2360 x 1330 截图和源代码作为替代证据。

## Overall Impression

当前页面的控件质量比整体布局好。输入框、单位、焦点和保存状态有可靠基础，但页面同时承担录入、日历、趋势、历史、身体同步和当日总览六类任务。最大机会是把记录页重新定义为“完成今天三项关键记录”，其他内容按需展开。

## What's Working

- 指标名称和单位直接，数值范围和未来日期限制减少常见错误。
- 保存状态使用文本和 live region，离线状态也有反馈，数据可信度基础较好。
- 颜色克制、圆角一致、没有装饰性渐变和重阴影，符合训练笔记的安静方向。

## Priority Issues

### [P1] 主录入任务没有成为页面主角

“关键记录 2/3”出现两次，却不直接说明缺少体重。用户必须在大量信息中自行诊断下一步。

**Fix:** 顶部改成行动状态：“还差体重”并聚焦缺失字段；完成后切换为“关键记录已完成”，提供唯一后续动作“记录训练”。核心录入使用开放式工作区，不再包在多层卡片里。

**Suggested command:** `$impeccable distill`

### [P1] 三栏结构重复展示同一批信息

左栏日历和右栏最近记录都承担历史导航；中央输入与右侧当天概览重复体重、热量、蛋白和完成度；右侧趋势又与复盘页职责重叠。

**Fix:** 删除左侧日期栏，日期、保存状态和导入合并为一条紧凑工具栏。桌面只保留“主录入区 + 轻量状态栏”两栏。日历和最近记录合并到一个历史抽屉，趋势回归复盘页。

**Suggested command:** `$impeccable layout`

### [P1] 日历在键盘焦点顺序中阻挡主表单

DOM 顺序让日期栏和 42 个日历按钮先于主录入字段。键盘用户可能需要经过约 50 个控件才能到达体重输入；紧凑日历单元只有 32px。

**Fix:** 主内容在 DOM 中置前，侧栏通过 grid-area 视觉定位；日历采用 roving tabindex，只保留一个日期进入 Tab 顺序；增加“跳到关键记录”链接；移除嵌套 main landmark。

**Suggested command:** `$impeccable audit`

### [P1] 保存与训记同步的心智模型仍不够清楚

“已保存”“从训记导入”“同步到训记”分散在不同区域，用户很难立即判断数据保存在哪里、哪几项待上传。

**Fix:** 在日期工具栏中使用一个集中状态模型：“LiftLog 已保存 16:44”“训记待同步 2 项”。读取固定使用“从训记导入”，身体写回固定使用“同步到训记”，失败和重试也在同一位置。

**Suggested command:** `$impeccable clarify`

### [P2] 等权卡片和常驻微调按钮制造视觉噪声

几乎每个区域都有相同边框、圆角和标题，六个字段同时展示十二个加减按钮，空值字段还显示浅色禁用按钮。页面因此显得机械和拥挤。

**Fix:** 页面只保留一个主表面和少量分隔线；统一使用产品字体，弱化过重的页面标题；微调按钮仅在字段有值或获得焦点时出现，并将目标值或上次记录作为更有用的辅助信息。

**Suggested command:** `$impeccable polish`

## Persona Red Flags

### Alex, power user

- Ctrl+Y 和 Ctrl+T 只存在于 tooltip，不容易发现。
- 日历优先的焦点顺序拖慢每天重复录入。
- 缺少“跳到第一个缺失字段”和“完成后开始训练”的连续路径。

### Jordan, first-timer

- 2/3 只说明未完成，没有说明具体需要输入体重。
- 空字段下的禁用微调按钮容易被理解为功能不可用。
- 日历、趋势、身体数据、训记和历史记录同时出现，初次使用时无法判断先做什么。

### Sam, accessibility-dependent user

- 42 个独立日历按钮进入 Tab 顺序，主表单到达成本过高。
- 中央和右栏重复的 aria-live 完成度可能重复播报。
- 嵌套 main landmark 可能让读屏导航产生混乱。
- 正面部分是输入标签、错误关联、焦点样式和状态文本已经较完整。

## Minor Observations

- 日期输入显示 `2026/07/10`，摘要和历史使用 `2026-07-10`。
- “接口字段说明”应移到训记连接设置，不应占据每日记录页。
- “记录”标题过于泛化，可使用“今日记录”或当前日期。
- 右侧五条最近记录与六周日历功能重叠。
- 身体数据的空 Suspense fallback 不提供加载反馈。

## Questions to Consider

- 如果体重是唯一缺失项，为什么六周日历比“记录体重”更显眼？
- 达到 3/3 后，产品希望用户结束记录、补充身体数据，还是开始训练？只能有一个默认答案。
- 如果趋势和最近记录只在用户打开“历史”时出现，真正会损失什么？
- 记录页到底是当天录入工具还是六周复盘看板？当前结构同时选择了两者。
